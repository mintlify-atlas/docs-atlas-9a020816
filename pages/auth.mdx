AETHON provides two authentication pages — `login.html` and `register.html` — that handle the sign-in and account-creation flows. Both are UI-only implementations: the forms render and validate visually using Bootstrap 5 classes, but they do not submit data to any backend or perform actual authentication.

## Login page

The login page (`login.html`) uses a two-column card layout. On medium and larger screens the left column displays a decorative cover image (`img/login.jpg`); on smaller screens the image is hidden with `d-none d-md-block`. The right column contains the form.

### Form fields

| Field | Type | Placeholder |
|-------|------|-------------|
| Correo | `email` | Ingresa tu correo |
| Contraseña | `password` | Ingresa tu contraseña |

### Additional controls

- **Login button** — a full-width dark `btn btn-dark btn-lg` button
- **Forgot password link** — an inline anchor (`¿Olvidaste tu contraseña?`) styled as muted text
- **Register link** — a paragraph below the button reading "¿No tienes cuenta? Regístrate aquí" linking to `register.html`

Both input fields use Bootstrap's `form-control form-control-lg` classes for consistent sizing across viewports.

```html
<!-- login.html — core form structure -->
<form>
  <div class="mb-4">
    <label class="form-label">Correo</label>
    <input type="email" class="form-control form-control-lg" placeholder="Ingresa tu correo">
  </div>

  <div class="mb-4">
    <label class="form-label">Contraseña</label>
    <input type="password" class="form-control form-control-lg" placeholder="Ingresa tu contraseña">
  </div>

  <div class="mb-4">
    <button class="btn btn-dark btn-lg w-100">Login</button>
  </div>

  <a href="#" class="small text-muted">¿Olvidaste tu contraseña?</a>

  <p class="mt-3">
    ¿No tienes cuenta?
    <a href="register.html">Regístrate aquí</a>
  </p>
</form>
```

## Registration page

The registration page (`register.html`) uses a single centered card with a dark color scheme defined in `css/register.css`. It has no image column — the form takes the full card width.

### Form fields

| Field | Type | Placeholder |
|-------|------|-------------|
| Correo electrónico | `email` | correo@ejemplo.com |
| Nombre de usuario | `text` | Tu usuario |
| Contraseña | `password` | Crea una contraseña |
| Confirmar contraseña | `password` | Repite tu contraseña |

### Additional controls

- **Registrarse button** — a full-width primary button (`btn-login-main btn-lg w-100`) using a custom class from `register.css`
- **Login link** — a line at the bottom reading "¿Ya tienes una cuenta? Inicia sesión" linking back to `login.html`

```html
<!-- register.html — core form structure -->
<form>
  <div class="mb-3">
    <label class="label-custom">Correo electrónico</label>
    <input type="email" class="form-control form-control-lg login-input" placeholder="correo@ejemplo.com">

  <div class="mb-3">
    <label class="label-custom">Nombre de usuario</label>
    <input type="text" class="form-control form-control-lg login-input" placeholder="Tu usuario">
  </div>

  <div class="mb-3">
    <label class="label-custom">Contraseña</label>
    <input type="password" class="form-control form-control-lg login-input" placeholder="Crea una contraseña">
  </div>

  <div class="mb-4">
    <label class="label-custom">Confirmar contraseña</label>
```

## Bootstrap 5 validation

Both forms use Bootstrap 5 form control classes for visual styling. The `form-control` class applies border, background, and focus-ring styles. To enable client-side validation feedback (green/red borders and helper messages), you can add Bootstrap's native validation pattern:

```html
<!-- Enable Bootstrap 5 validation on a form -->
<form class="needs-validation" novalidate>
  <input type="email" class="form-control" required>
  <div class="invalid-feedback">Please enter a valid email address.</div>
  <button type="submit">Submit</button>
</form>

<script>
  // Activate Bootstrap validation styles on submit
  document.querySelectorAll('.needs-validation').forEach(function (form) {
    form.addEventListener('submit', function (event) {
      if (!form.checkValidity()) {
        event.preventDefault();
        event.stopPropagation();
      }
      form.classList.add('was-validated');
    });
  });
</script>
```

<Warning>
Neither form currently includes a `required` attribute or `needs-validation` class. As shipped, the browser will allow empty submissions. Add these attributes and the validation script above before connecting the forms to a real backend.
</Warning>

## Registration flow

<Steps>
  <Step title="Fill in the registration fields">
    Open `register.html` and complete all four fields: email address, username, password, and password confirmation. Make sure the two password fields match before submitting.
  </Step>
  <Step title="Submit the form">
    Click the "Registrarse" button. In the current UI-only implementation the form does not POST to any endpoint. To wire it up, add an `action` attribute pointing to your backend route and a `method="post"` attribute, or handle submission via `fetch()` in JavaScript.
  </Step>
  <Step title="Redirect to the login page">
    After a successful registration response from your backend, redirect the user to `login.html` so they can sign in with their new credentials. The registration page already provides a "Inicia sesión" link at the bottom for users who already have an account.
  </Step>
</Steps>

<Note>
Both pages load the navbar via `loadComponent('navbar.html', 'navbar-placeholder')` on `DOMContentLoaded`. The footer is not included on either auth page.
</Note>
